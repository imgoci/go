# Technical Notes

- Use hexagonal architecture at all times. Keep business logic isolated from CLI, filesystem, network, storage, and other external adapters.
- Prefer functional testing before calling any feature complete. Unit tests are useful, but they do not prove the tool works the way the design intends.
- Take an agile approach to development. Avoid waterfall: underspecify when useful, prototype early, learn from the result, and refine from working behavior.
- This repo is the canonical Go implementation of the imgoci release format. Authoritative design: `.journal/001/ARCHITECTURE.md`; implementation map: `.journal/001/PLAN.md`. The normative spec is `~/code/imgoci/spec/spec.md` (stable, released v0.1.0, tag commit `8083159`); its `conformance/v1/{pass,fail}` fixtures are the validator test oracle.
- VERSIONING POLICY (session 008): the package version tracks this library's Go API and is DECOUPLED from spec releases. Format compatibility is carried by the imgoci media types (`.v1`; spec §4: a breaking format change requires new type identifiers), so one library version can support several spec releases. The README compatibility table + `testdata/conformance/SPEC_COMMIT` are the compatibility statement. Never mirror spec version numbers into the module version; a spec `.v2` is at most a PROMPT to consider `/v2`, decided by the Go API.
- Target shape: root `package imgoci` at module root `github.com/imgoci/go`; CLI is a private `cli/` submodule (bigoci pattern). Library deps stay minimal; each dep enters at the PR that first imports it (schedule in PLAN.md §1).
- ROOT PACKAGE IS A FACADE (session 009, PRs #27-#33). The root holds public types, sentinels, options, constructors, DTO mappers, nil/call-shape checks, and delegation — nothing else. 19 files / 1794 production lines; put new logic in `internal/`. Ownership map: `internal/index` = index codec + §6 rules + producer validation + §7.1 query grammar + the §7.2 `List` and §7.3 `Resolve` engines + `Entry`/`EntriesOf`; `internal/transfer` = orchestration, ports, `Classify`/`CommitFault`, `ValidatePublishSources`; `internal/adapters` = the per-repository adapter cache (`Pool`) and registry/multipart construction (`Open`); `internal/ociref` = reference grammar, sha256-only rule, digest-over-tag, `RequireTagOnly`; `internal/file` = destination mapping, staging, commit; `internal/auth` = credentials incl. `NewDockerCredentials`; `internal/e2e` = the container-gated e2e suite (`//go:build e2e`, imports the library as a consumer, so a test needing an unexported seam belongs in the root package instead).
- Internal packages CANNOT import root sentinels, so two wrapping shapes exist and the choice is per case: sentinel as SUFFIX (`destination missing role %q: %w`) -> internal returns a DETAIL-ONLY error whose text is exactly today's prefix and the root appends with `fmt.Errorf("%w: %w", err, ErrX)`; sentinel as PREFIX with a varying sentinel -> internal returns a CATEGORY (`transfer.Fault`, `*index.CapabilityError`) and the root owns both the choice and the wording. `errorlint` forbids a non-wrapping verb for an error, so `%w: %w` is the only lint-clean form and single-wrap errors necessarily become two-element multi-wrap ones; `errors.Is` is unaffected and no consumer walks `errors.Unwrap` on those paths.
- `index.Descriptor.Selector()` REBUILDS the six-field selector from the annotation map on every call. Never call it per entry on a query path: `index.EntriesOf` materializes selectors and the annotation-derived accessors once at parse time into `[]index.Entry`, which is what `Index` stores. Reading them per query instead cost `Resolve` 590% (3.1us -> 23.3us at 400 entries). Root's public-tree mapper cuts role and alternative slices from one backing array each with full slice expressions (cap == len), holding the whole campaign to a constant +3/+1 allocs/op. No benchmarks are committed; these numbers came from throwaway ones.
- Pins: `github.com/imgoci/bigoci` ≥ v0.2.0 (PushByDigest, casefold decode, identity coding, stable transport seam, upload wire re-hash — all required); `github.com/imgoci/go-oci-blob` v1.1.1 (inject transports, `RetryPolicy{}` = one attempt, own the outer retry budget).
- Canonical-bytes rule: never re-encode for identity; verify = `utf8.Valid` → decoded-dup-key scan → JCS transform (`gowebpki/jcs` v1.0.1, pre-audited 2026-08-15) → byte-compare. The transform is NOT a grammar validator and does not error on all violations — Decode must run first; the audit property is "errors OR output ≠ input". Tracked successor: stdlib `encoding/json/jsontext` once json/v2 leaves GOEXPERIMENT.
- Retry: exactly two non-nesting domains — this repo's loop for its own adapters, bigoci's internal budget for multipart calls (never wrap bigoci in retries; no public retry control exists there).

- Docker credential-store authentication is opt-in through `WithDockerCredentials`; anonymous behavior remains the default. Helper subprocesses inherit caller cancellation and have a 10-second ceiling; typed lookup failures never include secrets.
- Progress is one serialized absolute-snapshot contract across standard and BigOCI paths. Standard retries are observed through per-operation context state; BigOCI retains its separate internal retry budget and is never wrapped in the standard retry loop.
- RELEASE OPS: Release Please (`initial-version` consumed; manifest now `0.1.0`) opens release PRs on master; merging one creates the tag and a DRAFT GitHub release (`draft: true`), which then needs a manual publish (`gh release edit vX.Y.Z --draft=false`). Release app credentials on this repo are IMGOCI_*-prefixed (key at `op://Development/imgoci-release-please/key.pem`); bigoci still uses MEIGMA_*. When bumping SPEC_COMMIT: review the §5.4 registries against the between-pins diff, resync fixtures, bump the harness counts AND `cue_crosscheck.sh` minima, and grep the old pin/date repo-wide.
- Media-type comparisons are ASCII-only case folds everywhere — `strings.EqualFold` is BANNED for spec §4 comparisons (Unicode simple folding accepts U+017F/U+212A look-alikes).
- `ErrInvalidIndex` covers invalid retrieved imgoci documents (release index §6 AND file manifests §3.1); offline Resolve selection failures deliberately carry no sentinel in v1.
- Decoder working sets (zstd window, xz LZMA2 dictionary) share one ceiling: 128 MiB by default, configurable through `WithDecoderMaxWindow`, rejected at zero. NEVER hardcode this again — the old fixed 8 MiB refused `xz -9` (64 MiB dict) and `zstd --long=27` (128 MiB window), i.e. mainstream disk-image producer output. The bound is per active decoder, so peak memory is the ceiling times `WithWorkers`. xz completeness past the library's EOF gap is checked via a 12-byte footer ring; `ulikunitz/xz` `ReaderConfig.DictCap` is a FLOOR, not a cap (the zero value substitutes 8 MiB, and the library raises it to whatever the Block Header declares).
- Producer-only spec rules live in `internal/index/producer.go` and run from `Build`; `internal/index.Validate` must NEVER gain one, because spec §6:600-602 and §12 require consumers to accept producer-only violations. The §5.4 registries there are pinned to `testdata/conformance/SPEC_COMMIT`, and a test fails if the pin moves without a table review. Registry enforcement covers target/representation/usage/role/compression — architecture stays syntax-only because OCI owns that registry and evolves it independently of the imgoci pin.
- Usage (`io.imgoci.usage`, spec §5.3/§5.4/§7) is carried as ONE canonical serialized string, never a slice: rule 5 keys `map[Selector]int` and the §9 comparator must not allocate, so both `index.Selector` and public `imgoci.Selector` MUST stay comparable. `internal/index/usage.go` is the single parse/canonicalize/relate site. The public `Usage` is `struct{canonical string}` (not `type Usage string`) so no conversion can bypass `NewUsage`. Query fields stay `[]string` and are canonicalized once per call. Semantics differ by operation on purpose: `ListQuery.Usage` nil = no filter and matching is CONTAINMENT; `ResolveQuery.Usage` nil and empty both mean the EMPTY SET and matching is EXACT EQUALITY. `install-offline` requires `install` is a CONSUMER rule (§6 rule 4 in `Validate`) while registry membership is producer-only (`Build`) — the asymmetry is the part readers get wrong.
- Producer byte oracles (`internal/filemanifest/testdata/standard-v1.json`, `testdata/canonical/pass/minimal.json`) are independent artifacts. NEVER regenerate one with this repo's own encoder: a self-oracle round-trip is how a non-conforming `BuildStandard` stayed green through session 004. Canonical fail fixtures must be asserted by failing PHASE, not by `ErrInvalidIndex` alone, or they silently fail at an earlier gate than the rule they claim.
- Ops: `wt switch --create --base master` can race a just-finished pull and base worktrees on a stale tip — always `git reset --hard origin/master` after creating one. Local/CI golangci findings drift with identical configs; CI is the arbiter. Go pin is 1.26.5 (go-oci-blob v1.1.1 floor). Relative paths in subagent edits resolve against the session cwd, not the agent's worktree: give subagents absolute worktree paths and have them check `git -C <main> status --porcelain` before yielding (one agent still leaked edits into the main checkout in session 007; a sibling agent caught it).
- Subagent types: the `programmer` type failed en masse in sessions 002 and 006 (5/5 crashing at ~4m15s) but ran 9/9 clean in session 007, so it is no longer known-broken; the general-purpose `task` type remains the safe default (22/22 in session 006). Fan-out lesson: fencing an agent OUT of a file can cause the defect — "do not touch producer.go" was right about the §5.4 registry and wrong about the §5.2 annotation-location table. Fence by RULE, not by FILE, and give every file an owner, including anything the integrator writes.
- `cli/go.mod` carries `replace github.com/imgoci/go => ../`, so the private CLI is a SAME-PR caller of the library, not a downstream consumer. A change to the MEANING of an existing public default (not just an added field) breaks it immediately, and `root:check` will stay green if no CLI test exercises the combination. Sequencing CLI work into a later step is only safe for genuinely additive changes.
- Tooling traps: golangci-lint caches results per file path, so after `wt remove` it reports findings in the DELETED worktree until `golangci-lint cache clean`. `cue` on PATH may be 0.16.1, which refuses the spec module (`language v0.17.1`) and rejects even valid fixtures with a closed-field error — run the CUE cross-check through `mise exec`. When bumping `SPEC_COMMIT`, grep the OLD commit and date repo-wide afterwards: `doc.go` and `README.md` both claimed agreement with the pin file and silently went stale.
